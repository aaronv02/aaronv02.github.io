02 — INFERENCE

One socket, by design.

What actually happens each time the app asks the model for anything — the whole journey, end to end, on one loopback address.

FIG. 2 — LOCAL INFERENCE PIPELINE

Note — the model call is the process’s only outbound socket by design: standard-library HTTP (urllib), no SDK, no vendor client. Cancelling closes the stream, and closing the stream is what stops the daemon.

In plain terms —Every request to the model takes the same short walk: your approved words are wrapped in a legal guardrail and fenced as data, handed to a model running on your own machine, checked, and only then stored. Nothing in this drawing touches the internet.

  • +

In plain terms —Eight steps from your approved answers to a finished application, always in this order. The writing steps draft only from material you have approved; the last two are pure assembly — no AI involved, so nothing new can slip in.

FIG. 4 — STORAGE & EXPORT ZONES

In plain terms —Everything about your invention lives in the left-hand box, encrypted. Moving anything to the right-hand box is a separate action you take on purpose — a review PDF out, or a signed update in — and the working DOCX never crosses at all.

05 — MODEL ABSTRACTION

The model is a config line.

Not a commitment, and not a hope: the risky properties are enforced in code before the app will even start.

  • One configuration point.

    Runtime, model, and host are named once, in a single config module. Everything else in the codebase goes through the ModelAdapter interface — so swapping a runtime or a model is a config change, not a rewrite, and this site never hardcodes a model name either.

  • Gated before startup.

    Inventor text is untrusted input. A model hand-verified to obey instructions hidden in that text — or to leak its system prompt — is refused before the app will run, no matter how well it drafts. The eval harness is how those models were caught.

  • Independent review is a separate pass.

    The checks that challenge the draft can read from their own model config, so the drafter never grades itself on its own weights. Unset, review falls back to the drafting model — the seam exists today; choosing a specific reviewer waits on a real evaluation.

  • Offline even for tests.

    A deterministic fake adapter implements the same interface, so the whole product — and the whole test suite — runs with no model, no Ollama, and no network.

06 — PRINCIPLES

Rules the code keeps.

Distilled from the engineering docs. Each principle names its source.

  1. 01

    Rules are enforced in code, not asked of the model.

    The 150-word abstract limit is a counter. Figure numbering comes from the approved figure list. A co-inventor flag survives only if the words it quotes are an exact substring of the inventor’s own evidence. Where a rule is objective, Python holds it — the model proposes, the code disposes.

    SRC — DOCS/AGENTS.MD

  2. 02

    The agent that drafts never approves itself.

    The Quality Agent re-checks completeness, terminology, and claim support as an independent pass, instructed to find fault rather than endorse. The Security Agent does the same for protections: it verifies isolation, encryption, and auditability at run time instead of assuming them.

    SRC — DOCS/AGENTS.MD · DOCS/SECURITY-ARCHITECTURE.MD

  3. 03

    Model output is untrusted until validated.

    Inventor text is fenced as data at the prompt boundary, so it can never read as instructions — regardless of which model is loaded. Replies are parsed against a strict shape, and anything an agent cannot ground in the evidence is dropped, never shown.

    SRC — SRC/CLAIMFORGE/PROMPT_FENCE.PY · DOCS/AGENTS.MD

  4. 04

    Fail closed.

    A non-loopback config refuses startup. An export whose integrity or completeness cannot be stated is refused. An unsigned update never installs. Silence and errors both resolve to “no” — and the audit log records the refusal.

    SRC — DOCS/SECURITY-ARCHITECTURE.MD · DOCS/DEVELOPMENT.MD

  5. 05

    Every security claim has a test attached.

    ~790 automated tests run fully offline through a fake model adapter. An adversarial self-audit fires the real boundary attacks — traversal, planted content, forged updates — at the real refusal paths in CI, and a regression test proves the harness itself fails when a guard breaks.

    SRC — DOCS/SECURITY-ARCHITECTURE.MD · SITE.CONFIG — TECH_STATS

  6. 06

    Nothing leaves unless the inventor carries it out.

    Export is a separate, explicit act. Only the flattened PDF crosses — the exact bytes that were previewed, hashed at the crossing, written to one folder the inventor named. The working DOCX never leaves the vault.

    SRC — DOCS/SECURITY-ARCHITECTURE.MD

07 — DECISIONS & TRADEOFFS

Tradeoffs, on the record.

ADR 0001 records the stack. Three decisions shaped everything else — each with a real cost, paid knowingly.

  1. Decision 01

    A browser tab, not Electron or Tauri.

    ADR 0001

    Why

    Electron ships a second Chromium and a Node runtime into an app whose promise is “audit everything inside the vault,” and its ecosystem normalizes the auto-update and crash-reporting network paths we would have to rip out. Tauri splits the codebase across three languages. The machine’s own browser renders the UI, 100% of product logic stays in Python, and the entire UI transport is one auditable loopback socket.

    Cost

    The UI lives in a browser tab, not a branded native window. The call is isolated behind the loopback boundary, so a native shell can be adopted later without touching product logic.

  2. Decision 02

    Standard-library HTTP to the model runtime.

    ADR 0001

    Why

    Every dependency is attack surface to vendor, audit, and keep patched inside a network-isolated bundle. Talking to Ollama with urllib adds zero runtime dependencies — and the process’s only outbound socket stays that one loopback call.

    Cost

    No SDK conveniences. Streaming and cancellation are hand-rolled: completions stream as an incrementally readable response, and closing it mid-generation is what stops the daemon.

  3. Decision 03

    Hand-rolled DOCX and PDF renderers.

    ADR 0001

    Why

    A DOCX is a zip of XML; a PDF is a handful of indirect objects and a cross-reference table. Rendering both with the standard library keeps the runtime dependency list at three — and makes deterministic, metadata-free output possible: deliberately empty author fields, fixed 1980 timestamps, the inventor’s images embedded as their exact stored bytes.

    Cost

    The renderers carry their own obligations, all test-pinned — including the rule that a package holding fewer drawings than the inventor supplied can never describe itself as complete.
